# 后续确认：本轮结束后才进入，不自动启动

原 v2 S2 的确认资格只覆盖其事先冻结的主张与分析。本包新增谱指标、99%收益预算、协变 gauge 对照是看过 S1 后提出的，不能把 S1 中漂亮的相关性叫“独立发现”。

## 可执行的决策分支

**分支 A：短 CG 持续接近 full oracle。** 以机制/负结果为主；不启动新优化器。候选主张应是“哪些矩阵描述量不能代表任务作用/计算难度”，不是“所有网络的二阶问题都简单”。

**分支 B：至少一个非线性族在合格数值、有限成本下仍有稳定差距。** 只锁定一个主要可检验主张，再设计确认与实际训练收益。新训练之前固定 architecture、数据划分、solver、成本计账、主要端点、失败规则和分析。

**分支 C：误差归因主要是输入量化/精度。** 将方法学问题单列，不能把修改输入后的改善当算法改善。若只有一个 seed 支持，则维持局部观察，不立普遍漏检率。

## 建议的确认面板（提案，尚未启动/冻结）

- 选定本轮的 8 个 setting；每 setting 16 个新的 namespace seed：`GENESIS_NEXT_CONFIRM_V1`。
- 生成种子后与全部原 S1/S2 seed 清单做集合相交检查，任何重复都在首次训练前报错，不默默换种子。
- 每 seed 的 checkpoint 1、3，三 γ；只有 coarse。128 条新训练，256 状态，768 条件。这个规模只是候选上限，不是本包会花费的预算，也不保证功效足够。
- 先对**一个**主要端点做基于 S1 变异度的功效/精度模拟，固定样本数后再训练。不能“16 seeds”代替功效分析。
- 预先规定 setting 内 seed-cluster 配对估计与跨 setting 校正。缺失不能按观察到的效果方向筛除。
- 新确认的结果在训练/分析流程固定后才解封，不作反复顺序挑选显著状态。

这个训练阶段没有在本包中实现或自动启动。原因是本轮还没有裁决值得确认哪一个机制；现在启动完整新训练会重演“先烧算力再找主张”。本包已实现的范围是前一阶段的实际重测与机制裁决。

## 真正的优化器加速验证

只有当有明确可执行策略、数值资格和预测价值时，再做完整训练比较：相同初始权重/训练数据顺序、调参预算、随机化方法运行顺序、冷/热启动成本、特征/预条件器/参考获取成本全部记账；报告 fixed wall-time 与 fixed data budget，不能只报 matvec 数或局部二次型收益。

不把 full oracle 免费喂给策略；不在测试集/确认集上选择步长或启用规则。不因为强 baseline 表现好而删掉它。
